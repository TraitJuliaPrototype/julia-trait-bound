## 1. What is built, with commits

**The library** (TraitWorld `unified`: 5e2ef71, 362f08b, 5a9d19d, 6f86b4e):
- `Compiled{T}` (`src/compiled.jl`): the wrapper. `compiled_for(x)` is `TraitWorld.ByType.compiled_for`, an ordinary function that a module binds explicitly (`using TraitWorld.ByType: compiled_for`): the library still exports the cast of that name for the ports not yet converted (traits §7.6: the names are bound). Its operations forward through `_fwd`, as a box's do; its fields, `getproperty`, `setproperty!` and calls forward to the object; `unwrap`; `Compiled(d)` of a box is the wrapper of its object; `Dynamic{X}(w)` boxes the object.
- `@trait` declares `Compiled{Z} where {P…, Z <: X{P…}}` in `X{P…}`, forwarding by `object`; `Callable` likewise (`src/callable.jl`). The member hook skips the family as it skips `Dynamic`'s.
- `@default_dynamic` is recorded on the contract and does not set the compiler's default bit (step 4). `erases(X)` reads it, and `Callable`'s bit from Julia.
- `@erasing` (`src/erasing.jl`) at a method definition: for each argument typed by a trait that erases (a trait, an intersection with such a component, a `where` variable bounded by one), the method is defined at `Union{Dynamic{<:X}, Compiled{<:X}}`, and one forwarder per positional arity that holds such an argument: `f(@specialize(t::X), …; kws...) = f(_box(Dynamic{X}, t), …; kws...)`, compiled per member type, the box made by `jl_new_struct` without the membership test (its own signature has matched). With several such arguments the one forwarder boxes the plain ones (`_box_plain`). A parametric trait written bare or with `<:` parameters cannot be boxed there: the method is left as written. The kept-form method is defined before the forwarders.
- `convert(::Type{Dynamic{X}}, x)` and the identity at a box of `X`; `Dynamic{X}(d::Dynamic{X})` is `d`; a box of a subtrait is boxed at the trait without the test.
- D-3 (`src/atbox.jl`): `check_at_box(m)` reads the method's instance at `box_signature(m)` (each argument at a trait, a kept form or a `where` variable bounded by one replaced by `Dynamic{X}`; a free variable given the first of `Float64`, `Int`, `Symbol`, `String` its bounds allow), inferred by the facts rule and optimized. A fault: a call with a value at the box that finds no method (directly; below a call that only throws, the chain followed by re-reading each callee at its call's argument types and named; left to run time with no method at the known types), or that only throws (an undeclared field is named as such). Reported at the outermost frame's line: the line of the method that passes the value. `check_definitions` and the `bounded` refusal read it; the keyword sorter is skipped (its body method is read), the forwarders are skipped. A method whose body names a global not yet defined, or whose only faults are calls of the module's own functions with no method yet, waits for those names and at last for the module's end.
- Tests: `test/bytype.jl` (new); the attribute's, the classification's, fully typed mode's and the messages' tests follow the new rules. 90 testsets pass.

## 2. Choices made (mine)

- **The wrapper's name: `Compiled{T}`,** beside `Dynamic{X}`: the pair names what code is compiled for. `T` is the object's type, not a trait.
- **The forwarder's form: a macro at the method definition, `@erasing`.** It stands for lowering: Julia's lowering already makes several methods of one definition (a positional default, a keyword sorter). It decides by the traits' declarations when the definition is expanded; the runtime's method definition could decide by the evaluated signature with nothing written. `@default_dynamic` hooking definitions was not taken: the definition hook cannot narrow a method, and redefining one is not allowed while an image is built.
- **The kept forms as a `Union` of the two families,** not a type of their own: the argument is then no trait argument for the compiler, so the attribute's machinery stays out of the way, and dispatch ranks it above the forwarder at `X`.
- **The forwarder compiled per member type, with `@specialize`, boxing by `jl_new_struct`.** On this build `@nospecialize` at a trait argument takes the attribute's run-time path at each call (829 ns), and Julia's constructor tests the membership when it runs (110 ns). Once the attribute's machinery leaves (stage 4), `@nospecialize` is Julia's again and the forwarder can be compiled once.
- **The trait's own operation methods (defaults included) are not forwarded.** A plain member served by a default runs it as itself; the wrapper reaches it through `_fwd`.
- **An intersection erases where any component erases.**
- **A trait whose parameters the signature leaves open is not boxed there** (the box needs the parameters, traits §7.7).
- **No exception for Julia's own types** (step 4's): every plain member is boxed by the forwarder, `abs2` at a `Callable` argument included.
- **The wrapper's call method takes any arguments,** so a wrapper is a member of every `Callable` by Julia's rule, as every function will be under D-2. A wrapper of a function with no method at the signature reaches the forwarder, whose box refuses it where the value is passed (`TypeError`).
- **A box of the same trait is itself** (a library method of the box's constructor); a box of a subtrait is boxed at the trait without the test.
- **D-3's faults are calls that find no method or only throw.** A call left to run time that finds a method when it runs is Julia's barrier, no fault: E-397's `setproperty!` with a name that is no constant passes now. `typeof(t)` and `Wrapped(t)` are bounded.
- **The ports' trait modules declare `first_seen = false`**: D-1 has no fallback by scope.

## 3. The cases that would change D-1

- **One gate row lost with no fix in the library: a plain member at each call is boxed at each call** (E-402, row 3: 25.4 ns against 7.3). Recorded in open issue 186 and GT-19, with the rule (the forwarder boxes at the call; a box is a heap object, and on this build its construction tests the membership when it runs) and a proposal (fold the box's member test with an edge on the membership so a forwarder inlined into a typed caller needs no box; erase at the door). For the user: D-1 is provisional.
- Not cases: a forwarder was generated for every form the two pieces use (keyword methods, optional arguments, a `where` variable, three and four trait arguments); no ambiguity came from the forwarders (one seen came from a signature of mine, `Type{<:VertexModel}`, and went with it); NetworkDynamics' workload is not worse.

## 4. What the stage-2 references must say that the addendum does not

- **The box's construction by a forwarder needs no membership test,** and a box of the same trait is itself: otherwise each re-boxing costs a run-time query (E-402, E-403). Compiler: the member test of `Dynamic{X}(x)` folds where `x`'s type is known (an edge on the membership).
- **The forwarder's shape:** one per positional arity that holds an argument at an erasing trait; keywords passed on whole; several trait arguments boxed by one forwarder that passes kept forms as they are; the kept-form method is the one documented and is defined first.
- **Which arguments erase:** a trait that declares the default, `Callable`, an intersection with such a component, a `where` variable bounded by one; not a trait whose parameters the signature leaves open (`t::Column`, `t::Column{<:Real}`): there the argument takes a plain member as it is.
- **The trait's own methods** (an operation's method, a default) are not forwarded; a plain member served by a default runs it as itself.
- **`unwrap` on both forms; `compiled_for(d)` of a box is the wrapper of its object; `Dynamic{X}(w)` of a wrapper boxes the object.**
- **The wrapper's reach includes every `Callable`** by its call method (consistent with D-2): the signature is checked where it is boxed.
- **D-3's fault classes:** a call that finds no method (directly, below a call that only throws, or at run time with no method at the known types), a call that only throws (an undeclared field); the report names the line of the method that passes the value and what the call reaches. A call left to run time that finds a method is no fault. Not read: a method whose box cannot be formed (a bare parametric trait, a bare `Callable`).
- **The check's instances belong in the cache with edges** (D-3 says kept and validated with the image): the prototype's are at stand-in types and are dropped at a load (92 log entries at the ODE port's load, E-404). The references should name the instance at the box as the one the erased code runs, so the check's reading is that code's own inference.
- **Storage typed `Dynamic{X}` converts** by `convert(::Type{Dynamic{X}}, x)`, the identity at a box of `X`; a late load of it ends nothing (E-404).
- **A module of the new design has no fallback by scope** (`first_seen` leaves with the attribute; until then the ports declare `first_seen = false`).
- **`@nospecialize` at a trait argument is Julia's** once the attribute's machinery leaves; until then it takes the attribute's run-time path (829 ns a call on this build).
