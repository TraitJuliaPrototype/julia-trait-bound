**Choices (mine), and why.**
- **`Kept{X}` leaves.** With the choice in each element's type, `Vector{X}` holds what `Kept{X}` held. No layout gain (an element of `Vector{Kept{X}}` was a pointer and a flag; of `Vector{X}`, a pointer), and `Kept{X}` was no member, so code went through `kept_call`.
- **The forwarder is `@nospecialize`,** as the addendum wrote it. In its code at the declared type the box's field test is decided by the declared type; inlined into a typed caller, by the positive membership with an edge (W-160 (a)). The prototype's per-member-type forwarder is the deviation T-125, for a reason that leaves with the attribute (C-112). The builder may find per-member-type cheaper; the reference then changes with a measurement.
- **Both kept forms in `Core`.** A forwarder made by Julia where a method is defined must name both families; `compiled_for` stays the library's function.
- **The forwarders are made by the runtime's method definition** (`jl_method_def`), from the evaluated signature: lowering cannot know whether a name is a trait that erases. Each forwarder records the method it forwards to, so that a redefinition or a deletion takes it along, and reflection shows one definition. `@trait`'s own methods carry `Expr(:meta, :no_forwarder)`.
- **Julia's default outer constructors get forwarders,** as any method: `ODEProblem(lorenz!, …)` boxes whichever constructor runs.
- **No `with_dynamic`, no `@default_compiled`.** A box needs its trait, which a value-level function cannot know; a trait without `@default_dynamic` takes a plain member as it is.
- **The closed build's rule restated for the wrapper:** a call whose method's static parameter a value known only by its trait binds (the wrapper's constructor) branches over the members. It generalizes the cast's branches (5d8da002fa).
- **Compiling ahead does nothing per member for a method that erases:** its box instance is the definition-time check's, in the method's own package.
