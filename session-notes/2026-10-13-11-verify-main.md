# 2026-10-13 — Session 11: verified mains and compiled binaries

## Intent

The design says little about compiled binaries. The user's proposal: use the
trait machinery on a "main" to guarantee that every call hits compiled code;
that requires the main to be fully trait compliant. Refined: it requires the
main's whole reachable closure to be trait compliant (the closure rule), which
the design rejected for packages but which costs no composability at a main.
Build it, document it, have Fable review it.

## Done

- **`TraitRegions.verify_main(f, argtypes; compile, entrypoints)`**
  (`TraitRegions/src/verify.jl`, exported with `isclosed`). Walks
  `code_typed` IR from the entry; classifies calls as static, bounded
  (concrete/small-Union argtypes, `@nospecialize` positions, or methods on
  concrete types), trait (seal lookup, projection, entry→worker, witness
  call; targets enumerated from the seals), guard (slow path, not followed),
  or hole (kinds: dispatch, callee, splat, latest, builtin, inference, eval,
  closure, trait_arg, noscan). Error-path holes (as first built; corrected
  after the review, below): statement cannot reach a value `return`, or code
  reached only from such statements or from calls inferred `Union{}`. Reports normal-path method instances without native
  code (`ci.invoke != C_NULL`), and audits every enumerated worker for piracy.
  `compile = true` hints the entry plus every trait and bounded target;
  `entrypoints = true` registers them with `Base.Experimental.entrypoint`,
  sets `CLOSED_WORLD` and switches the guard off (honoured by `__init__`).
- **`@seal` compiles the seal's own code** (projection at T, witnesses at R)
  while a package image is being built (`_compile_seal_code`). Found by the
  verifier: conformers without a workload shipped seal closures inferred
  (by `build_seal`'s return-type checks) but without native code, and no
  downstream image can add native code to an upstream CodeInstance.
- Tests: 60/60 at first (14 new in "verify_main"); 64/64 after the review. `poc/errorsplit` scenarios still
  all as expected.
- **`poc/verifymain/`**: VMApp/VMAppW (minimal program, verified vs
  workload-only build), EcoApp/EcoAppW (ecosystem), `observe.jl`
  (prediction vs `--trace-compile`), `makie_holes.jl`, `trim/` (juliac).

## Lessons

1. Trait dispatch is dynamic dispatch with an enumerable target set; the
   prediction is exact. A seal is what makes the set of types finite for
   generic code; plain Julia is bounded only when methods are on concrete
   types (a closed method table), not for generic code on runtime types.
2. The verified build closes the ownership gap for its application.
3. Seal code belongs in the conformer's image, compiled, not just inferred;
   fixed in `@seal`.
4. In a trimmed binary a hole is a crash; the enumeration is load-bearing.
   A trimmed binary also needs the bounded targets of the machinery itself
   (`_enter_slow`), and cannot run the guard (no IR, no reflection).
5. Type instability inside a region worker is a hole; the verifier is a
   whole-closure type-stability check. `ColPlots.histcounts` has a real
   boxing bug (left as is: earlier measurements used it).
6. Makie's display path is dynamic at its core; trait discipline in user
   code cannot close it.

## Limits

Models compiled code by re-running inference; does not follow holes (counts
are a frontier); error-path holes in caught exceptions still compile;
`invoke`/finalizer/atomic-modify/opaque closures are holes without analysis;
projections and seal lookups over-approximate (all seals of the traits
involved); not thread-safe.

## Review (Fable 5.1, high effort) and fixes

The reviewer reproduced all numbers (tests, both observe suites, trim, Makie)
and found false CLOSED verdicts, each with a script:

1. CRITICAL: `f(@nospecialize(x::T)) where T` is specialized per runtime type
   (`jl_compilation_sig` keeps typevar positions); counted bounded; a trimmed
   binary died with `MethodError`. Fixed: `_nospecialized` requires a declared
   type without free type variables.
2. CRITICAL: "cannot reach a value return" was read as "on the way to a
   throw": a server loop ending in `jl_exit`, a main ending in `exit(0)`, and a
   `try`-recovered exception were CLOSED yet compiled `plainsum` at runtime.
   Fixed: doomed = least fixpoint from throw sinks (throw/rethrow/error
   ccalls; `Union{}`-typed dynamic calls except `exit`; `Union{}`-typed
   invokes unless the callee can neither throw nor return); statements in a
   `try` are not sinks; a three-level reach (error / normal / protected)
   propagates callers' `try` regions to callees.
3. MAJOR: task closures (`@async`, `Task`, `Threads.@spawn`, `@threads`,
   `atexit`) invisible. Fixed: `jl_new_task` (inlined `Task`), `Task`,
   `atexit`, `finalizer` arguments become roots.
4. MAJOR: the `@seal` hint was a no-op for witnesses with abstract declared
   argtypes. Fixed: `_seal_witness_sigs` scans the registered ops' workers at
   R and compiles witnesses at the signatures they call (checked with a
   package: `pick(r, i)` now native at `(R, Int)`).
5. MAJOR: `entrypoints = true` switched the guard off in any build. Fixed:
   only when `Base.JLOptions().trim != 0`.
6–7. MINOR: witness enumeration merged traits with equal witness names
   (now restricted to the enclosing worker's trait); op-less traits missing
   from the registry (now collected from seals too).
8. MINOR: `--trace-compile` blind to shared-code instances and inference.
   `observe.jl` now also reports the cumulative compiler time (reported via a
   raw ccall so that reporting compiles nothing).
9. Guard in warn mode: observed 0 compiles, not a guarantee (documented).

Framing taken over: the verdict is per world and per seal set; "nothing
builds on a main, but a main builds on everything".

After the fixes: tests 64/64 (18 in "verify_main", 4 of them the review's
counterexamples); the reviewer's six `ce_closed.jl` cases and four
`ce_task.jl` cases report OPEN with the offending hole on a normal path; the
trimmed `@nospecialize` app reports its hole. Observation suites unchanged
(all exact; compiler time 0.0 ms for verified builds, 0.2 ms for VMAppW
with no native compile). Makie: 28 / 16 / 79 (59 distinct) normal-path
holes; witness targets 12 instead of 14 (trait-restricted).
