# 2026-08-09 — Session 03: M0 spike results — ALL GATES PASS, go for M1

Code: `spike/M0Spike/` (package, 4 lowerings of 4 ops), `spike/scripts/e1..e5`.
All numbers Julia 1.11.7, `--startup-file=no` (Revise in the user's startup.jl
pollutes measurements — always disable for experiments).

## The four lowerings compared

| path | witness storage | worker instances | new-type compile cost | steady-state |
|---|---|---|---|---|
| `direct` | — (ordinary dispatch on `T`) | per-`T` | full: every op body recompiles per `T` | fastest |
| `erased` | `FunctionWrapper` table | **1 per op** | wrapper construction ~30 ms/closure (cfunction) | ≈ direct on chunky ops |
| `dyn` | plain `Function` fields, return-type asserts | **1 per op** | **~0 (dict store) + witness-body compile only** | ≈ erased |
| `fc` | raw NamedTuple (`@full_compile`) | per witness-set | worst (worker + witnesses per set) | fastest |

## Headline (E2: fresh session, never-seen type, 4 ops incl. one heavy body)

| mode | register (compile ms) | first-4-ops (compile ms) | total |
|---|---|---|---|
| **dyn** Plain | 4.3 | 9.7 | **14 ms** |
| erased Plain | 34.2 | 4.3 | 38 ms |
| direct Plain | 0 | 70.7 | **71 ms** |
| fc Plain | 7.7 | 98.4 | 106 ms |
| dyn Lazy (bespoke broadcast witness) | 3.6 | 51.1 | 55 ms |
| direct Lazy | 0 | 96.3 | 96 ms |

**5× less compilation for a realistic conformer, and the dyn/erased cost is
independent of region size** (heavy `summarize` op cost the same ~2 ms entry
overhead as tiny `colstd` — worker bodies come precompiled from the pkgimage),
while direct scales linearly with op count × body size. The Lazy rows show the
honest floor: a genuinely new witness body (a fresh broadcast expression) must
compile in every path (~40 ms); nothing can share code that has never existed.

## Gates

- **(a) overhead amortizes** (E1): fixed ~30–90 ns per entry (dict lookup +
  indirect/dynamic witness calls). Ratios vs direct: 10× at len=16/trivial op,
  1.0–1.5× at len=256, ~1.0 at len=4096. Chunky ops ⇒ noise. dyn ≈ erased.
- **(b) pkgimage reuse** (E2): confirmed — workers `cached=true` from the
  image; never-seen type triggers zero worker compilation.
- **(c) stale pointers** (E3): FunctionWrappers *tracks* top-level method
  redefinition (re-derives pointer; no stale execution observed at top level).
  dyn has **no stale window by construction** (dynamic dispatch, always latest
  world). Weaker than feared in the plan.
- **(d) KILL CRITERION — unrelated churn** (E4): 38 invalidation trees from 50
  new types + methods on Base functions + new seals + redefinitions; **zero
  touching M0Spike workers**; post-churn calls compile 0.0 ms; worker MI count
  still 1. Same for dyn. **Core thesis holds.**
- **Sharing** (E5): 12 types × 3 ops → erased worker MIs = 1 each; direct = 12
  each. With `@nospecialize` entries, even entries are 1 MI *total*.

## Design findings (feed into M1)

1. **`@nospecialize` on entries and registration is essential.** Without it,
   each per-`T` entry costs ~6.6 ms and registration kwcalls specialize per
   closure type. With it, entries compile once ever and live in the pkgimage.
2. **Plain-`Function` witness tables (dyn) beat FunctionWrappers** for this
   design: ~10× cheaper registration (no cfunction), no stale window, equally
   invalidation-immune (dynamic calls create no inference edges), same
   steady-state cost on chunky signatures. FunctionWrappers' remaining
   advantage — signature enforcement — can be had with a seal-time check
   instead. **M1 default: dyn tables; wrappers optional.**
3. **fc-path closure-type subtlety**: syntactically identical closures share a
   type, so fc "per-T" counts can collapse in synthetic benchmarks (e5 showed
   2, not 12). Real per-type witnesses differ, so real fc cost is per-T.
4. Witness-body compilation is the irreducible per-type cost. Realistic
   accessor witnesses ≈ 5–10 ms; exotic bodies (broadcast chains) cost what
   they cost in any design.
5. Measure with `--startup-file=no`; `@timed` (1.11+) gives
   `compile_time`/`recompile_time` directly; straight-line top-level timed
   expressions avoid both world-age errors and `invokelatest` compile noise.
