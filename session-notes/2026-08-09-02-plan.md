# 2026-08-09 — Session 02: mandate, plan assessment, start of implementation

## Mandate (from user, this session)

- **Principal aim: dramatically reduce compilation in Julia — approach Python's interactive feel.**
- Secondary: improve correctness, remove performance cliffs.
- Prototype in pure Julia if possible; compiler modifications only if necessary.
- The PoC's job is to **start a discussion in the Julia community** — speedups matter less than a credible, discussable design.
- Do not adopt the Background plan uncritically; streamline if needed. Work autonomously; report at substantial progress.

## Assessment of the Background plan

The Background plan (TraitRegions.jl, Rung 1) is fundamentally aligned with the mandate: its core bet — erased workers keyed per *representation* `R` instead of per user type `T`, called through witness tables — is exactly a compilation-reduction mechanism. Claims map to the mandate as:

- **C1 (O(1) worker compilation across N types)** and **C2 (fresh session + never-seen type ⇒ near-zero compilation)** are the *headline* for "approach Python interactivity". C2 especially: TTFX for a brand-new user type hitting precompiled native code.
- **C3 (bounded invalidation)** is the "stay fast over a long interactive session" claim — also core.
- **C4 (opt-in concreteness) / C5 (fail-early)** serve the secondary goals (correctness, cliff removal) — keep, but deprioritize.

**Streamlining decisions** (vs. the Background plan):

1. **M0 expanded, still the kill-gate.** Fold the pkgimage fresh-session TTFX test (E2-lite) into M0 from day one — it is the headline number and the riskiest claim; no point building macros if it fails. M0 = hand-written spike + four experiments (overhead, fresh-session TTFX, stale pointers, churn invalidations).
2. **M4 (sealed-interpreter Rung-2 spike) deferred indefinitely.** Deep unstable internals, not needed to start a community discussion; mention it in the writeup as future work.
3. **M2 trimmed:** fingerprints + blame diagnostics kept (they make the invalidation story concrete); the full *prescriptive* allowlist audit and TraitCore curation reduced to a v0 sketch — the writeup states the closure rule's cost honestly instead of paying it fully.
4. **M1 macros kept but minimal** — the community-facing surface syntax must be readable (`@trait`/`@seal`/`@region`), but object-safety/associated-type checking can be best-effort.
5. **Deliverable reframed:** repo + experiment numbers + a design writeup suitable as a Discourse/GitHub-discussion post. Headline metric: *compilation time for the first operation on a never-before-seen type, fresh session*, erased vs. ordinary Julia.

**Pure Julia**: Rung 1 needs no compiler changes. Confirmed the approach stays Julia-only.

**Julia version**: develop on **1.11.7** (`julia +1.11.7`); `@timed` there reports `compile_time`/`recompile_time` directly. Smoke-test on 1.12 later.
