## 2. Choices (mine)

In the references and the decision log (§3, "One way to erase, the compiler's choices"); open issues §1 lists them.
- **The expansion hook, not a runtime bit.** The runtime asks the library at `jl_method_def`, as it asks it at a member's first use (the member hook) and at a definition (the definition hook). The library owns the contract and the wrapper type; the runtime makes the methods. About 60 lines of C.
- **One statement flag for every type test inference proves** (`IR_FLAG_TYPES_PROVEN`), not the nothrow flag: a store's nothrow covers its bounds check too.
- **A membership's method is a fact for the deep class**, as an absence edge's pair is.
- **The forwarder is compiled per member type where only the member's own type fixes a parameter of the trait** (`ip::IndexProvider{I}`): the box needs the parameter.
- **A `where` variable another argument names is not boxed** (a struct's own constructor `T{F}(f::F)`), nor a `Callable` whose parameters only the argument would bind.
- **The box is made in the forwarder's body by `new`.** In code compiled by facts, a call of a library helper with an argument typed by the set is a run-time site; its result is unknown.
- **The walk's replay at the method's own signature** where one signature with the member does not say what the membership adds. The replay passes over the method's own entry, and the callers that matched it before keep their code, so the method's instances stay.
- **The check infers apart** only where Julia's cache keeps no code or the box's call runs another instance.
