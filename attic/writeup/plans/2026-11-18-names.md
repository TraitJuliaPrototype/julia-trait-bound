# The names of the directories: part 9 of the documentation clean-up

**Status:** done (2026-11-18; W-162 closed). Was: adopted with [the clean-up's plan](2026-11-18-documentation-cleanup.md) (part 9; the user, 2026-11-18: "Clean Up the directory names as well, but do it last."). The steps below are the main session's (mine). Not normative.

## 1. What changes

There is one implementation. A directory's name says what it holds, without the name of the work that made it.

| Today | After | What it is |
|---|---|---|
| `TraitWorld-unified/`, `TraitDifferentialEquations-unified/`, `TraitMakie-unified/`, `TraitTables-unified/`, `TraitCSV-unified/`, `TraitReport-unified/`, `forks-unified/` | `TraitWorld/`, `TraitDifferentialEquations/`, `TraitMakie/`, `TraitTables/`, `TraitCSV/`, `TraitReport/`, `forks/` | the library, the demonstrators and the forks: each repository's branch `unified` |
| `TraitWorld/`, `TraitDifferentialEquations/`, … `forks/` (the main checkouts, on the branches of October 2026), `TraitWorld-port/`, `TraitDifferentialEquations-w96/` | `pre-unified/TraitWorld/`, … `pre-unified/forks/`, `pre-unified/TraitWorld-port/`, `pre-unified/TraitDifferentialEquations-w96/` | the library on Julia 1.13 and its demonstrators: the tag `pre-unified` of each repository. History |
| `experiments/unification/` | `experiments/implementation/` | the gates, the acceptance cases and the experiments of the implementation |

**What keeps its name, and why.**
- **The Julia trees** are named by their branch: `julia-next/` (`next`, the head), `julia-unified/` (`unified`, the tag `prototype-2026-11`: the regression control), `julia-vanilla/` (v1.13.2), `julia-1.13/` (the earlier line; it holds the repository). Renaming a built tree of 3 GB gains nothing.
- **`TraitWorld-base/`** and the trees under `wt/`: the regression control's library and demonstrators at the tag.
- **`ndport/pkgs/NetworkDynamics-unified/`**, `Graphs-unified/`, `GraphMakie-unified/`: the port's worktrees beside upstream's clones of the same packages, which the baseline needs. There the suffix names the port's branch.
- **The branch `unified`** of each repository. A branch's name is the repository's own.
- **Logs** name the paths of their runs. They are records.
- **The attic** (`attic/`, `experiments/attic/`) and the session notes: history, with the paths of their day. [The attic's index](../../attic/README.md) says how an old path reads now.

**Not done here: the default branch on GitHub.** It is a setting of each repository, and this host has no tool for it. The final report gives the command.

## 2. The steps

No agent works in the trees while this runs. Every repository is clean and pushed first.

1. **Check:** `git status` and `git log origin/<branch>..` in the seven repositories, `experiments`, `ndport` and the design repository.
2. **Move the checkouts.** For each of the seven repositories `R`:
   - `mv R pre-unified/R`, then `mv R-unified R`;
   - `git -C pre-unified/R worktree repair` with the paths of all its worktrees, so that the repository and each worktree find each other;
   - `git -C R status` is clean and names branch `unified`.
3. **Rename** `experiments/unification` with `git mv`.
4. **The paths in files,** by one script, in tracked files and in the environments' Manifests and Projects (tracked or not), outside logs, the attics and the session notes:
   - `R-unified` becomes `R` for the seven names;
   - `experiments/unification` and a path component `unification/` become `implementation`;
   - the design repository's `.gitignore`, `mkdocs.yml`, the website's script, `env.sh`, `tools-local/`; `CLAUDE.md` for the paths only.
5. **Check, on `julia-next`:**
   - the gates (`experiments/implementation/gates/run_all.sh julia-next '*'`) and the stages' gates;
   - the library's suite; the examples of `intro/`;
   - each demonstrator's suite: the ODE library, the plotting library, the table library and the CSV reader, the report's check, the forks' session digests, NetworkDynamics' subset;
   - the lint and the quote check of the documents.
6. **Commit and push** each repository; the state page's heads; the setup page; the record's index.

**If a check fails** that passed before the rename, the cause is a path. It is fixed at the path, or the step is undone (`mv` back, `git worktree repair`, `git checkout` of the files), and the report says so.
