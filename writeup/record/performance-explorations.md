# Further performance explorations

**An archive.** The speed work is retired ([`CLAUDE.md`](../../CLAUDE.md); [the decision log](decisions.md) §5). No entry is added, and none returns to the work queue by itself. The entries are read for ideas.

Each entry says what it is, what was measured, why it was not pursued, and what would make it worth pursuing. This page holds the entries that concern the implementation as it is. The entries of the library on Julia 1.13 (PE-1 to PE-20, but PE-5) are in [the attic](../../attic/writeup/record/performance-explorations-earlier.md).

| PE-32 | **Instances the system image holds without machine code, compiled in every session:** the system image keeps some instances inferred only (`iterate(::Enumerate{Vector{Symbol}})`, `issorted(::Vector{String}, ::ReverseOrdering)`, `getindex(::Vector{Float64}, ::Int)`). A package image whose code calls one without inlining reuses that instance and stores no machine code for it, so the JIT compiles it in each session. Two ways out: a package image stores an instance of its own with machine code where the instance in force lives in another image without it; or the system image compiles what it infers. PE-28's `iterate(::Enumerate{Vector{Symbol}})` is this pattern, not untyped check code. | E-351 (2026-11-10, `unified` 352b916899's source, TraitWorld 1ea6af9, one traced session): 8 of the 28 instances compiled in the goal's task, 45.6 of 309.7 ms; the imports alone 4 of 6, 34.4 of 73.5 ms. Found by `experiments/implementation/audit/image_uncompiled.jl`. | General Julia behaviour that facts and traits neither cause nor remove; 2.5 % of the goal's 1.83 s; a change to what images store (`Compiler/src/typeinfer.jl` `collectinvokes!`, `src/staticdata.c`) with its own risks. | The tool's count grows with a port (it runs on any compile trace), or work on what images store is taken up for another reason. |
