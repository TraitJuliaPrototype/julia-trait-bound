# X3, slice 4: a recipe with a recipe child; `Attributes` and `Observable` as user types

Status: **adopted** (2026-10-29, mine; W-70). Not normative. The slice W-70's finish line names first: "the slice with recipe children and `Attributes`/`Observable` as user types" (the user, 2026-10-29: "I agree with your finish lines"). It follows [slice 1's plan](2026-10-28-x3-waist-slice1.md) and serves [the lean-core memo](2026-10-27-lean-core-old-apis.md) §1.2.

## 1. The question

- Does an upstream recipe whose `plot!` calls another recipe run unchanged above the trait core?
- Does the child take the parent's attributes as upstream passes them, `Attributes(plot)`, and follow a change of them?
- Can a user pass an `Observable` as an argument or an attribute and see the plot follow at the next render?
- Can a group of recipes with a dependency of its own (StatsBase) load as a package of its own, a second joint owner of the umbrella (the memo's table "What loads when")?

## 2. The recipe

`stephist` from upstream's `src/stats/hist.jl` (Makie 0.24.16). Its `plot!` derives the bin edges and the step points with `map!`, then calls `stairs!(plot, Attributes(plot), plot.points; color = plot.computed_colors)`. So the tree is `stephist` → `stairs` (slice 1's recipe, upstream's file) → `lines` (a leaf, a core primitive).

- The file is included unchanged, so `hist`'s recipe and `plot!` are defined too. `hist`'s `plot!` calls `barplot!`, whose file (`barplot.jl`, 460 lines: stacking, dodging, labels) this slice does not include. Its names exist; calling `hist` fails.
- `hist.jl` also holds `convert_arguments(::Type{Stairs}, ::StatsBase.Histogram)`. It is checked too: it ends in `convert_arguments(P, xs, ys)`, the cascade's fallback to the conversion trait.

## 3. What the slice builds

**In the umbrella (`TraitMakie.OldAPI`), names and types:**
- `Attributes`, upstream's type: a dictionary from names to values. A value may be a node of a plot or an `Observable`.
- `Plot{F, T}` keeps its arguments as given (`args`), beside the converted ones.
- The names `hist.jl` mentions at its top level: `heatmap`, `voxels`.
- `@joint_owners MakieCompat MakieCompatStats`.

**In the layer (`MakieCompat`), the machinery:**
- `Observable`, Observables.jl's type, re-exported (the ecosystem's type, not a new one). The layer re-exports it, not the umbrella: a new dependency of the umbrella would have to be resolved into every environment that holds TraitMakie.
- **Arguments converted again** when an argument's value changes: the conversion is a node of the plot's graph, over the arguments as given.
- **Observables, pushed at the edge and pulled at the render:** an `Observable` in an argument or an attribute is read at each use. A listener (`on`, plain code) marks the plot's nodes stale when it notifies, so an array changed in place and then notified is followed too.
- **Recipe children:** `name!(parent::Plot, attrs::Attributes, args...; kw...)` makes an old-style child plot. The child takes each of its attributes from the keywords, else from `attrs`, else its default. Values taken from the parent are references to the parent's attributes and nodes, so the child follows a change of the parent.
- **The plot's attributes as `Attributes`:** `Attributes(p)` and `p.attributes` hold references to the plot's attributes; `shared_attributes` returns `Attributes`; the leaves take them.
- **A user's property API:** `p.name[]` reads, `p.name[] = v` and `p.name = v` write; `p[k]` is argument `k`, and `p[k][] = v` replaces it.
- **The cascade's fallback:** `convert_arguments(P, args...)` converts by `P`'s conversion trait; a recipe without one takes its arguments as they are.
- The names `hist.jl` uses: `automatic`, `extrema_nan`, `AbstractPlot`, `BarPlot`, `Heatmap`, `Voxels`.
- The hand-over stays the `Plot` trait's three operations: a child plot is drawn by its parent, plain code.

**A new group, `MakieCompatStats`** (`TraitMakie/compat/MakieCompatStats/`): upstream's `hist.jl` unchanged, StatsBase, a precompile workload as a recipe package would have. StatsBase loads only with it.

## 4. Checks and measures (E-226)

**Correctness:** by bytes where both sides are drawn by the core's `Lines` with equal points, else by pixels (`experiments/x3/tools/pngdiff.jl`):
- `stephist` against TraitMakie's own `stairs!` through the step points that StatsBase gives for the same edges: the default bins, and `bins = 8` with `normalization = :pdf`;
- the parent's attributes changed after the plot is made (`bins`, `step`, `color`): the child follows;
- an `Observable` argument replaced (`obs[] = y`), and an array changed in place then `notify(obs)`;
- an `Observable` attribute (`color`) changed;
- `Attributes` given as an argument and splatted as keywords; `Attributes(p)[:bins][] = 5`;
- `stairs!(fig, fit(Histogram, x))` through `hist.jl`'s own conversion;
- slices 1–3's checks unchanged.

**Ownership:** the census of the group's methods on the umbrella's names (`experiments/x3/census.jl`).

**Costs** (2 fresh processes each): `using` and the first PNG of a `stephist` with an `Observable` argument, with and without the workloads (PrecompileTools' preference `precompile_workloads = false` for MakieCompat and MakieCompatStats); after a late `using DataFrames`, the next PNG and the CodeInstances inferred for it. TraitMakie's own `stairs` and slice 1's old `stairs`, as before.

**Would change the design:** a part of the old API (recipe children, attributes passed by reference, Observables) that the layer cannot provide without a rule the references refuse; a hand-over that needs more than the `Plot` trait's operations; Observables needing trait code in the notification; an old recipe over the core recompiled by the late load.

## 5. Not in this slice

- `hist` → `barplot` (`barplot.jl`).
- The PlainPlots control for this slice.
- `on` and `lift` of a plot's attribute; `used_attributes`; `SpecApi` (`to_plotspec`, `plottype`).
- Observables read by the core's own recipes: TraitMakie's `stairs!(fig, obs)` would need `Observable{T}` to conform by forwarding for the whole family ([traits §4.7](../reference/traits.md#47-families), T-7).
