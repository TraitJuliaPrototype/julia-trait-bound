## Findings, by severity

### H1. The slot's miss path raises a hard error where plain Julia runs — verified in the code, scenario by reasoning

`jl_code_slot_resolve` (`src/gf.c`, after `code_slot_find`) ends in `jl_error("code slot: the callee's code does not match its caller")` when it finds no CodeInstance of the callee that is valid in the task's world, has the caller's result type (`same_type`, uncommitted; `jl_egal` in 7500630036), has the policy, and has the entry the site needs (`code_slot_entry`: a specialized `specptr` for a specsig site; never `jl_fptr_const_return`). A bound call has no such failure mode. The call site reaches it when:
- **the task runs in an older world and the caller came from an image** (`target == NULL` in imaging mode, `src/codegen.cpp` `emit_code_slot`): `code_slot_find(mi, world_old, …)` finds the old CodeInstance only if it is compiled or compilable (`code_slot_entry` returns 0 for `invoke == NULL` without compiling; only `jl_fptr_wait_for_compiled` is compiled, through `jl_read_codeinst_invoke(…, 1)`); otherwise `jl_type_infer_policy(mi, world_old, SOURCE_MODE_ABI, …)` infers the callee again in the old world and the result must be `same_type` with the one the caller was compiled against. Inference is not deterministic across contexts (recursion limits, a cycle's order, `max_methods`): where it differs, the site raises instead of calling the old code that is still valid there;
- **the re-inference folds to a constant** (`jl_fptr_const_return`): `code_slot_entry` refuses every such CodeInstance, `jl_type_infer_policy` returns the same one again, and the site raises;
- **the callee's only entry is the interpreter or the boxed `jl_fptr_args`** while the site is specsig (a module under `compile=min` that is still inferred, or a CodeInstance whose compile failed): `code_slot_entry(ci, 1)` is 0, `ci2` is already "compiled", and the site raises.

The gate (`slot_cascade.jl`) exercises the old world only through `invoke_in_world` on JIT callers whose `target` is valid there, which never reaches these branches.

**Fix.** Never `jl_error` on a miss. Sound fallbacks exist: (a) call the callee through its generic entry (`invoke(ci, args)`) and assert the result to the caller's result type, which is sound because the caller's inference was sound in that world (the callee's value *is* of that type there); the boxed path `emit_slot_call` already emits for non-specsig sites can serve, chosen at run time by a flag the resolver returns; or (b) make the mark final and have the site dispatch (`jl_apply_generic`) with the same assertion. Add a gate case: an image caller, a task in an older world, and a callee whose old CodeInstance was never compiled.

### H2. Revalidation from inside inference is re-entrant inference without cycle detection across the nesting — reasoning, unverified

`typeinf_edge` (`Compiler/src/typeinfer.jl`, the new `elseif interp isa NativeInterpreter && !force_inline` branch) calls `jl_revalidate_for_inference`, which runs `revalidate_code_instance` and, for each result edge not valid in the latest world, `jl_type_infer_policy` — a fresh `typeinf_ext_toplevel` with a new interpreter, while the outer frame is still being inferred and holds its engine reservation. The cycle `stack` is local to one `revalidate_marked` call; `jl_engine_reserve_policy` (`src/engine.cpp`) answers a reservation held by the same thread with an uncached placeholder and lets the inner inference proceed.

Shape: X infers; its callee Y is marked; Y's result edge Z is invalid; Z calls X. Inner inference of Z reaches `typeinf_edge(X)`: the engine's same-thread fallback hands it a placeholder and X is inferred a second time; that reaches Y again (still marked, the first revalidation uncommitted), revalidates it again with a fresh `stack`, infers Z again, reaches X again. Nothing bounds this. The shape needs a result edge inside a recursion: possible when a cycle member's CodeInstance is in its cache before the caller's `finish!` runs (`slot_callee` checks `jl_mi_cache_has_ci`), which depends on the order `finish_cycle` finishes the frames.

The plan's §2.6 ("Inference does not revalidate") was the design that avoided this; the plan's status line records the change and the reference lists "inference's cache miss" among the lookups, so the record is consistent, but the change got no gate case for a recursive shape (the gate's cascade is a straight chain).

**Fix.** Either take the plan's §2.6 back (inference infers a marked callee again, as the plan said; the cost is one inference, which the session's numbers do not show to matter), or make revalidation refuse to run while the current task is inside inference (a thread-local depth, or `ct->ptls->engine_nqueued > 0`), or keep one thread-local `stack` across nested calls so that the second visit of Y fails as a cycle. Then a gate case: a mutually recursive trio with a result edge, redefined so that the third member is invalidated through its edges.

### M1. `JULIA_CODE_SLOT=0` is not a safety valve, and E-283's "bound call" baselines are a mix — verified

The switch is read at codegen and in the walk; the system image was built with it on. `logs/e283-session.log` shows the slot=0 sessions resolving **794 slot misses** (`columns`), 788 (`ode`), 1,107 (TraitWorld's tests): Base's code in the image keeps its slots whatever the switch says. `slot_cost.jl` guards against this for its own loops (it asserts the miss count), so the +0.08 ns figure stands. The session and image comparisons compare "new code without slots over an image with slots" against "everything with slots"; the plan's §2.7 ("a safety valve") and the reference's wording ("the code it compiles binds every call") describe less than a user would read into "off". Soundness is unaffected: with the switch off the walk invalidates every caller, and the image's slot sites still resolve through a world-checked miss.

**Fix.** State in compiler §3.3, the plan and evidence §4 that the switch governs code compiled after it is read, that `sys.so` keeps its slots, and that the sessions of E-283 (3) measure that mix. A true valve needs the system image built with the switch.

### M2. The exclusion of inlined callees rests on debug-info edges; no gate pins the shape that would keep stale inlined code — reasoning

`slot_result_edges` excludes a callee as inlined when its MethodInstance or Method is the `def` of a `DebugInfo` reachable from `src.debuginfo.edges` (`inlined_defs!`). `ir_inline_linetable!` (`Compiler/src/ssair/inlining.jl`) pushes the inlinee's `DebugInfo` for every inlined item, so on reading this is complete for `InliningTodo`, `ConstPropResult` and `SemiConcreteResult` items. But it is an indirect record: a callee inlined at one site and invoked at another (a call-site `@inline` beside a plain call of the same MethodInstance, or a `VolatileInferenceResult` inlined once and invoked once) appears once in `edges` (`count == 1`) and would be a result edge if its debug-info edge were ever missing or carried a `def` that is not a `MethodInstance` or `Method`. That is the one misclassification that keeps **stale inlined code** on an equal result — the exact fault the slot must never produce — and `slot_cascade.jl` has no such case (its callees are `@noinline`).

**Fix.** A gate case: one callee inlined at one site (`@inline f(x)` at the call) and invoked at another in the same caller; redefine a method the callee dispatches to so that its result stays equal but its code changes; the caller must be compiled again, not kept. Better still, take the record from the inliner's own list of inlined CodeInstances (`add_inlining_edge!`) rather than from debug info.

### M3. The walk of a revalidation is unlocked; the commit checks the world counter and the caller's own mark, not the callees — reasoning

`revalidate_code_instance` reads the edges and asks `ci_valid_in` for each without a lock, infers callees, then commits under `world_counter_lock` if `jl_world_counter == world` and the caller is still marked with the same `max_world`. Every invalidation that comes with a world increment (a method defined, deleted or replaced; a binding replaced) is caught by `same_world`. An invalidation without one is not: image validation on another thread (`Compiler/src/reinfer.jl` through `jl_invalidate_code_instance`) can lower a callee's `max_world` after the walk checked it, and the commit restores the caller anyway. The slot then still resolves the result-edge callees by result type, so the damage is a callee with equal type but different effects or exception type reaching a caller that assumed the old ones. Low probability; not covered by any test.

**Fix.** Under the lock at the commit, re-check `max_world` of every CodeInstance the walk accepted (`edges` and `newedges`), or take the lock for the walk where no inference is needed and re-walk after an inference.

## What was checked and holds up

- **The mark and the walk** (`_invalidate_backedges`, `mark_code_instance`): a mark only where `replaced_ci != NULL` (a callee invalidated through its own edges, never one replaced at its signature, which goes through `_invalidate_backedges(mi, NULL, …)`), `invokesig == NULL`, and `jl_ci_has_result_edge`; the walk goes on from a marked caller; a later invalidation clears the flag (`invalidate_code_instance`); a second result-edge invalidation of an already marked caller is a no-op, which is right because its callers were walked at the first mark. A caller with a code edge to a marked callee is invalidated. Verified.
- **The record's conditions** (`slot_result_edges`): every `:invoke` of the callee typed by its result (`===` on types is structural, so a union split's `typ` counts only where it equals the callee's result); a single CodeInstance in `edges`; excluded where a match list, an `invoke` pair, a bare MethodInstance, a non-plain `CallInfo` (constant propagation, concrete evaluation, `invoke`, `_apply_iterate`, opaque closures) or a debug-info edge names it; the callee Julia's own, no opaque closure, in its cache. The `VolatileInferenceResult` case is right: it is the callee's own inference handed to the inliner. Verified.
- **The two parsers agree** on every edge kind `stmtinfo.jl` writes: `Int`-led lists, `(Type, CodeInstance | MethodInstance | Method | MethodTable)` pairs, bare `CodeInstance`, `MethodInstance`, `Method`, `Binding`, `MembershipCell`, `MembershipEntry`. `ForwardToBackedgeIterator` gives list targets `invokesig == nothing`, and the Julia side marks list targets bad, so the C side's `invokesig == NULL` test cannot promote one. Verified.
- **Intermediate worlds**: the new callee must have `min_world <= markworld` and `max_world >= world`; restoring the caller's `max_world` to `~0` is then sound for every world since the mark. A later mark of the same caller cannot move `markworld`, so a second callee invalidated later fails the `min_world` test and the mark becomes final: conservative. Verified.
- **The equal-result test** (`ci_result_equal`): return type, exception type, constant, const-return entry, IPO effects. Sufficient for what a caller can take from a result edge, given that the record excludes inlining, constant propagation and concrete evaluation.
- **Images mask the flag**: `src/staticdata.c` writes `flags & (NATIVE_CACHE_VALID | FACTS | G2)`, a pre-existing whitelist. The record travels in `analysis_results`, kept by the generic serializer; the gate's image case prints `record: true`. Verified.
- **GC**: a slot holds only a CodeInstance that is in its MethodInstance's cache (`slot_callee` at record time; `code_slot_find` and the resolver's `target` at run time); caches never drop entries (`jl_mi_cache_insert` only inserts). The raw `target` pointer is emitted in the JIT only; images get `NULL`. Verified.
- **The task's world**: `get_tls_world_age` is the world at the function's entry, which is the world the caller's own validity is judged in. Verified.
- **W-114's runtime commits**: e81cd49a67 (a membership adds no method, so `which(m.sig)` is still `m`: keeping `LATEST_WHICH` is right); 5f2373b2d5 (the check is inserted after `run_passes_ipo_safe` and before `ipo_dataflow_analysis!`, the frame's effects are forced in `adjust_effects`, the hook runs in the latest world and restores the task's world on a throw; the deletion hook runs before the lock, so a refusal changes nothing; `jl_method_set_source` keeps the policy bits and the mode bits apart); 0ce5b7f752 (L5). Verified.
- **The library's classification** (d281762) against traits §7.3: `_stores_in_slot` accepts a store into a field or element whose type is a supertype of the trait (`Any` included, as §7.3 reads); `_equation_function` accepts `f(t)` for a function of `Self` an equation names; a splat is a use; a call into another module's unannotated function is a use at the call (`_in_contract`'s last loop: `p === Any && m.module === interp.mod`), so counting uses only in the method's own module makes no method bounded that is open. Verified.
- **The shadow query** (51a143a2f6): comparing the function's own type is right; without it every constructor shares the index under `Type`. Verified.
- **The ports' translations** follow the design as stated (`@specialize` for `Opened{X}`, the bare trait for `Kept{X}`, `@nospecialize` for a `Dynamic{X}` argument, families with a bounded variable, plain members in `Vector{Column}`), and open issue 157 is recorded with the case, the rules and proposals; the assertion at each barrier is marked as the interim. Verified.
