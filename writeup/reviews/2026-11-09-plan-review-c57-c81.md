## Summary

Both fixes are at the rule and both are sound. Build both, with changes:
- **C-57.** The one-line fix is right, and it is verified at every path that stores a `CallSigBackedge`: the session, the image's validation at load, and the invalidation in `gf.c`. The plan's soundness argument is incomplete, though: it argues from the dispatch backedge alone, while the same backedge carries the callee's *own* invalidation to the caller, and for an instance compiled once at a set that invalidation can come from any member's package (verified by a probe). The design admits it (the result edge, the code slot), but the plan, the reference and the gate should say so. The images will keep more plain code; that needs a registry row and a load measurement, not only a count.
- **C-81.** The contract slot is the right home. But the plan inherits the slot's hole: a package's contract on another image's type is silently lost at load (verified: the whole contract, not only its candidates), and nothing refuses it. Refuse it in `jl_declare_contract`. The package gate is a real test of survival once it also covers a split precompiled into the image, a type past the candidates and the refusal of a late registration.

## Findings, by severity

### C-57

#### 1. The fix is sound at every path — verified

- **The forward edge is the fact at the call's signature.** `_add_edges_impl` (`stmtinfo.jl:170–197`) stores `(1, info.atype, ci)` where the match's instance is wider than the match (`mi.specTypes !== m.spec_types`): one match, fully covering, at the call's own `atype`. The code's assumption is "at `atype`, only this method matches"; the instance that runs is the method's, valid for every argument of its signature. That assumption changes only where a new method meets `atype`.
- **The session's backedge is `svec(sig)`** (`typeinfer.jl`, `ForwardToBackedgeIterator` and `store_backedges`); verified in the probe: `skip(::X21).backedges = [svec(Tuple{typeof(skip), A21}), g21's CI, h21's CI, svec(…), FM.fg's CI]`, for the plain and the facts caller alike.
- **The image's validation checks the call's signature, then stores the same backedge.** `reinfer.jl:235–239`: for `edge isa Int`, `sig = callees[j+1]` and `verify_call(sig, …)`; its fast path (`:510–530`) accepts where the wide instance's `dispatch_status` has `METHOD_SIG_LATEST_ONLY`, which `jl_method_table_insert` clears when any part of the instance's signature is replaced (`gf.c`, `jl_atomic_store_relaxed(&mi->dispatch_status, 0)` under `replaced_dispatch`), so it is sound for the narrower `sig`; its slow path (`:591–600`) runs `_methods_by_ftype(sig, …)` at the call's signature and compares methods. A validated CodeInstance then goes through `store_backedges(child, child.edges)` (`:357`), the same iterator as a session.
- **Invalidation meets the call's signature.** `_invalidate_dispatch_backedges` (`gf.c:3318–3327`) intersects the new method with `callsig` and asks `is_replacing` over that intersection. `ambig` is per method pair (`gf.c`, `char ambig = !morespec[j] && !jl_type_morespecific(method->sig, m->sig)`), independent of the instance, so reusing it for the narrower intersection is right. The instance-level filter before it (`is_replacing` over `type ∩ mi->specTypes`) is monotone: every method that covers the larger intersection covers the smaller, and each can only make `is_replacing` answer no; so "not replaced at the instance" implies "not replaced at the call", and no invalidation at the call's signature is skipped. Deletion and redefinition go through `invalidate_backedges(mi, NULL, …)`, every edge, conservative.
- **The callee's own invalidation reaches the caller as through any edge:** `_invalidate_backedges` (`gf.c:3213`) treats `jl_is_svec(invokesig)` as a plain edge.
- **The predicate flips the right cases** (the probe, the plan's rule evaluated on the build's records): `g21` (plain, `@noinline` callee at the set), `g21i` (inlinable callee) and `FM.fg` (a facts caller) go from G2 clear to G2 set; `h21` (a caller at the set, edge `Tuple{typeof(skip), X21}`) and `d336` (a caller at `Any`) stay clear. **The facts caller is the real loss today:** facts code at a fact signature calling a method with the set's default `Dynamic` is not G2 on `b05ae361e0`.

#### 2. The soundness argument omits what the same backedge carries — verified by a probe (medium)

- The plan's "Why sound" argues from the dispatch backedge: a method defined later invalidates the caller only over the intersection with the call's signature. True. But the backedge also carries the callee's own invalidation, and the callee here is an instance compiled once at the *set's* signature, whose plain code holds edges at the set: every member's package can change them.
- The probe: `skipf(x::X21) = foo(x)` with `foo(::X21)`, compiled once at `X21`; callers `g21f(::A21)` (plain) and `FM.fgf(::A21)` (facts), both G2 under the plan's predicate. Then a second member `B21` and `P21.foo(::B21) = :fooB`, the shape of another member's package. Result: `skipf(::X21)`, `g21f` and `FM.fgf` all get `max_world = 39685`, and after the next call both callers have new CodeInstances. A G2 caller at `A21` was compiled again by a definition that names neither `A21`, `g21f`, `skipf` nor `X21`.
- This is within facts §2.2's letter: the callee's result changed (`Const(:foo)` to `Symbol`), "a change of a callee's result it holds a result edge to", or a code edge where the caller used the constant; the code slot (§3.3) keeps a caller whose callee's result is unchanged. And the same holds today for a per-type plain callee whose body has an abstract call. What is new is the reach: for an instance compiled once at a set, the "stakeholders" of the callee's result are all the set's members' packages. Under the facts policy the callee's call at the set is a run-time site and nothing of this happens; it is the product setting's plain callees (Base's, a plain package's) that carry it.
- **Change to the plan:**
  - "Why sound" states it: the dispatch fact is the call's; the callee's result is a result edge, revalidated by the slot, and for a callee compiled once at a set its result can change by any member's package. One sentence in compiler §3.2's status, or facts §2.2's "Scope", says the same.
  - Gate `n21` gains the probe's case, pinning both outcomes: a method at another member that changes the callee's result compiles the G2 caller again; one that leaves it unchanged (`foo(::B21) = :foo`, both constants equal) keeps the caller through the slot. Whether the caller's edge is a result edge (the `:invoke` typed by the callee's result, `slot_result_edges`) or a code edge (a constant used) decides which; the gate asserts what the build does.
  - `m3_g2_counts` ("non-stakeholder definitions lose zero G2 CIs") is in the run, since the set of G2 CIs it counts grows.

### C-81

#### 6. A contract on another image's type is silently lost at load; nothing refuses it — verified (medium, the one real hole)

- The probe's package declares `jl_declare_contract(Base.AbstractDisplay, svec())` beside its own. After the image loads, `jl_has_contract(Base.AbstractDisplay) = 0`: the slot is a field of the system image's `TypeName`, which an incremental image never writes back (`staticdata.c`, a `TypeName` of another image is a reference, not an object). The operations are lost with it, not only the candidates. The same happens at `using` without a precompile, since `using` precompiles in a child.
- The references say "its declaring module writes the contract" (§7.1) and "the concrete subtypes its declaring module registers" (§7.2), but for `IO` the type is Core's and the contract Base's, so "declaring module" means the contract's declarer, and nothing says the type must be the declarer's own image. The plan puts the candidates into the same slot, which is right, and so inherits the hole for both.
- **Change:**
  - `jl_declare_contract` refuses a type whose `TypeName` is in a loaded image (`jl_object_in_image(tn)`), with an error naming the rule. Base's build passes (Core's `IO` is in no image yet); a package or the prompt declaring on `AbstractString` is refused. The rule in §7.1 and traits §3.4: a contract is declared in the type's own image (Base for Core's types). Gate `n19` (0): `jl_declare_contract(AbstractString, …)` raises.
  - Mine, for the user to confirm (open issues §1), since it closes the prompt's experiments on Base's types. The alternative for the record: a list of foreign contracts in the image, activated at load as the memberships are; a second mechanism for a case no port needs.

#### 7. The write-once contract fixes the candidates for good; say what that closes (medium)

- With the candidates in the slot, no module can add to a closed type's candidates after its contract is declared, which is §7.2's rule. Two consequences the plan should record:
  - Today any module can append to `IO`'s candidates: the probe's `jl_register_candidate(IO, Base.BufferStream)` from `Main` made it the fifth. The refusal closes it; `n19`'s new assertion covers it.
  - Open issue 170: a stdlib's stream (REPL's `LimitIO`) can never be among `IO`'s candidates, since Base's `iotrait.jl` cannot name a type defined after it. 170's proposals (a) and (c) remain; a registration from the REPL does not. Note it in 170.
- The declaration must follow every candidate's definition, since the slot is written once: true for `iotrait.jl` today; a comment there saves the next reader a search.
- `jl_register_candidate` keeps TraitWorld safe: the member hook runs only where the method's parameter is an open set (`gf.c:7046`, `name->open_set`), and `implement.jl:460` registers for a trait; neither reaches a type with a contract. Raise at a type with a contract; elsewhere, for a non-set, stay a no-op as today, or raise too, but say which.

#### 8. The package gate is a real test of survival; make it cover the split (medium)

- The harness of `n18` (a fresh depot, a child to precompile, a separate child to load) discriminates: on the head, after the load, `has_contract(A) = 1`, the operations are there, `candidates_of(A) = []`, and the call at `Vector{A}` compiles to a dynamic call with the declared result asserted (the probe). After the fix the same session must show both candidates and a split.
- **Change, so that the gate says more than "the svec survived":**
  - the candidates' methods are not leaves (as `n19` does, so the branches' `:caller_world` pointers are visible), and the gate counts them or asserts the `isa` tests;
  - one call at `Vector{A}` precompiled into the package's image (`precompile(callop, (Vector{A},))`), asserted kept at load (its CodeInstance valid, `max_world == typemax`) and giving the right answer for each candidate, and one compiled in the session;
  - a subtype past the candidates, through the table;
  - `jl_register_candidate(PkgC.A, PkgC.S1)` raises after the load (today it silently re-registers, the deviation's workaround).
- The svec's types from other modules: a candidate is a concrete subtype of the type, so a dependency cannot be one (the type is defined later) and a dependent is refused; a package's candidates are its own types. Only the system image's `IO` holds candidates from a module other than the type's (Core's type, Base's streams), in one image. The plan can say so and drop the worry.
