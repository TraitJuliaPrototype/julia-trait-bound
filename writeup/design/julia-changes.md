# The changes to Julia, as built

The inventory of the [compiler reference](../reference/compiler.md): what the patched Julia (`julia-1.13/`, branch `trait-world-1.13`, on v1.13.2, with branch `split-table` on top) adds, as of 2026-10-28, with commits, files and upstream status. For core developers. Where this chapter and the reference disagree on what is intended, the reference wins; this chapter wins on what is built.

Size (00dcc9994c): 65 commits on v1.13.2 (with build scripts and the dispatch profiler), 43 files, about 2,460 lines added. The largest file is `Compiler/src/facts.jl` (580 lines), which holds the facts mode's rules.

## 1. The facts compiler: parts (A)–(D)

| Part | What | Main files | Commits |
|---|---|---|---|
| **(A)** a facts mode of the native interpreter | `NativeInterpreter` has `facts::Bool` and `owner`. Under facts, a call is inferred, with its edges, only at a fact signature (`is_fact_sig`: a dispatch tuple, its union splits, unions of concrete elements in tuple arguments up to four, a closure's call at kinds, a concrete `Vararg` tail). Any other call is a run-time site (`FACTS_ABSTRACT_SITE`). `return_type` folds only an answer that cannot be wider than plain inference's, else plain inference's answer when it rests on facts, else at run time (`PlainRTInterp`, its own cache owner). A plain caller of a facts method gets a separate facts inference (`facts_edge`) and names that CodeInstance. Reflection of a facts method is facts inference. | **(C)** dispatch from facts code | Code of owner `:facts` calls `jl_apply_generic_facts` and `jl_invoke_facts` at run-time sites: the same method lookup, then the callee's facts code, compiled on a miss. This covers the calls codegen emits (direct calls, `invoke`, `_apply_iterate` with known tuples, `invokelatest`). Dispatch that goes through the runtime's `jl_apply` (splats of unknown length, `jl_call`, `@cfunction`, finalizers, task entry) runs the callee's default owner's code: a facts method's facts code, a neutral method's plain code in the product setting, which is not trait code. That is the intended rule ([facts §5](../../attic/writeup/reference/facts.md#run-time-sites); `../reviews/2026-10-19-compiler-implementation.md` §2.4). | `src/gf.c`, `src/codegen.cpp` | c3415abde6 |
| **(D)** the `Dynamic` call-site split | `Compiler.split_call(K, RT, f, x, args...)`: inferred as `f` at the union of `K`'s registered candidates (at most four, each split a fact, `register_dynamic_candidate!`, no edge), plus a fallback. The inliner union-splits it with the dynamic call last, never "fully covered" (`SplitCallInfo`); it asserts the fallback, and any case not known to be an `RT`; the join is typed `RT`. A later implementation reaches the fallback and invalidates nothing. **The last branch** calls through a table of the call's targets keyed by the value's type: `jl_split_table_ptr` (`src/gf.c`) probes the table of the call's signature (`SplitTable`, `facts.jl`; emitted by `split_table_call!`, `ssair/inlining.jl`), a miss makes a `:caller_world` pointer to `Base._SplitTarget` or `_SplitTargetFacts` (`base/splittable.jl`), and the call goes through it, typed ([compiler §4.3](../../attic/writeup/reference/compiler.md#43-what-follows-the-split-the-table-of-a-calls-targets)) | `facts.jl`, `ssair/inlining.jl`, `stmtinfo.jl`; `src/gf.c`, `base/splittable.jl` | f6838f96fc, 67f5c0bcc8, bc26aa9255, 711484a23e, 6d480d0753 |

**The switch.** `JULIA_COMPILE_BY_FACTS=1`, or a system image built with it (`experiments/factscompiler/scripts/build_facts_sysimage.sh`), compiles all code by facts under owner `:facts`: the test bed. Without it, only facts methods are compiled by facts: the product setting. The switch decides only the default owner (`jl_default_owner`, `src/gf.c`; the facts system image's default read when the image is restored, `jl_read_facts_image_default`, `src/init.c`), and an interpreter's mode is its owner (W-22, 8ceda6f9d6). `--trim` turns the facts mode off: a trimmed image writes no facts flags (`jl_method_is_facts` is false under trim).

## 4. Upstream status

- **Ready as they are** (general fixes, small):
  - 40512f64c2 (the run-time `return_type` entry in the image);
  - bb82a82bbf (reflection in the compiler's world for an explicit `NativeInterpreter`; upstream has no `owner` field, so there it is one line);
  - pieces 10, 9 and 17.
- **After broader measurement in plain Julia:** the two inliner changes of §2 (exact specializations over a widened varargs tail; cycle members inlining each other). The system image grows 0.4% with both.
- **General improvements of 2026-10-19, to measure in plain Julia and propose:**
  - exact-type entries in the per-call-site dispatch cache (a9d3dcb345), which speeds up dynamic calls to `@nospecialize` methods in any code;
  - the `cfunction` calling convention `:caller_world` (piece 18);
  - `known_type` (b5bb9ab881).

  The cross-owner inlining (c7f1eae1c0) and keeping facts copies in images (9892bfc288) matter only with a second cache owner, so they go with the proposals for (B) and (C).
- **Proposals:**
  - (A) as "a facts mode for the native compiler", with the benchmark table ([the rationale §2.3](../design.md#23-step-3-the-facts-rule-extends-the-guarantee-to-code-that-is-not-fully-typed));
  - pieces 1, 1′, 14, 15 with strict mode;
  - (B) and (C) as per-method inference modes;
  - traits in the type system (piece 7) last.
- **A bug fix, to propose on its own** (W-57; julia-1.13 b13a4fb810, 4d21a039ef; on `unified` 74882bd25b, 4a43550691, 60b7e90aa4, §7.1; whether to propose: W-19, waiting for the user): Base's type-introspection helpers read a type's fields with `getfield`, take sizes, offsets and field types from builtins or the runtime, and call each other through `invoke` at the callee's own signature. The framing, without the facts mode, which only exposed the problem:
  - **Undefined behaviour by Julia's own contract.** The `@assume_effects` docstring (`base/expr.jl`): assertions "are made for all world ages. It is thus advisable to limit the use of generic functions that may later be extended to invalidate the assumption (which would cause undefined behavior)." The helpers assert `:foldable` or `:total` (`padding`, `array_subpadding`, `isabstracttype`, `unwrap_unionall`, `fieldcount`, `datatype_alignment`) yet go through generic functions a package may extend for its own type (`getproperty(::Type{Foo}, …)`, `sizeof(::Type{Foo})`). Such an overload makes the assertions false, and the answer then depends on compilation: a folded call keeps the value it had when compiled, with no edge to the dispatch inside it, while a call that runs consults the overload.
  - **Fewer invalidations.** Each generic call at `DataType` in the helpers is a method-table dependency: a package adding `getproperty` or `sizeof` methods for its own types invalidates the Base code compiled over them. Reading the type's data directly removes it.
  - **Base's own practice, applied consistently.** Stock Base already reads `getfield(dt, :layout)` in a sibling helper (`runtime_internals.jl`), and `reinterpret`'s code notes that `Stateful` "makes this vulnerable to invalidation".
  - **The limit, stated:** upstream may call an overload that intercepts `:name` or `:layout` on a type object a misuse, and the change hardening rather than a fix. The evidence that would settle it: a short demonstration in stock Julia, a package's overload and `isabstracttype` or `reinterpret` giving different answers folded and unfolded (to build before proposing).
  - **The observable change:** Base no longer consults a user's overloads of these functions on their own types inside its introspection (the cases: methods added to the helpers themselves, `getproperty` on a type object intercepting internal field names, `sizeof` or `fieldoffset` for a type; one error type in `padding`, `TypeError` for `MethodError`, on a path `reinterpret` never reaches).
- **Not for upstream:** the facts-only parts of §2 (the Compiler's never-by-facts flag, `leaves_to`).
