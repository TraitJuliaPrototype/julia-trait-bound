# The evidence: what is measured, and what is not

A chapter of the [rationale](../design.md): the measurements behind the design, for core developers. Each number names its experiment and build; the current builds are in [state.md §6.1](../state.md#today).

**The builds.**
- **The measurement round of 2026-10-20:** julia-1.13 3b8085c222 (branch `trait-world-1.13`), TraitWorld bed3782. Every number in this chapter is from it unless its row names another build.
- **The run of 2026-10-27** (E-163, E-164): the round again, on julia-1.13 26a407d988 with TraitWorld main bbfc130 (the heterogeneous rows on TraitWorld 9fd18db, branch `basetraits`); logs in `experiments/overnight-2026-10-21/logs/`, write-up in its README. Where it agrees with the round within the runs' spread, the round's numbers stand and the run is noted; where it does not, its numbers replace the round's, marked with its date, and the round's are kept as "before".
- **Rows not in the round** keep their build: mostly julia-1.13 61852d8fb1 with TraitWorld 375a930 (2026-10-19), called "the build of 2026-10-19" below.
- **Before/after:** where an older number for the same quantity is kept, it is marked "before" with its build.

[The summary](#summary-what-the-evidence-shows-and-what-it-does-not) says where each axis of [the goals](../goals.md) has its numbers in this chapter; the standing itself is the goals'; [`performance.md`](performance.md) says where the costs come from. The round's raw logs are in `experiments/factscompiler/round/logs/` (`run.log`, `callbench.log`, `untyped-{plain,all}.log`, `sites-{plain,all}.log`, `quick.log`, `bench.log`, `compare-full.log`, `compare-plain-vs-s28.log`, `demonstrators.log`, `g2all-{interleaved,before}.log`). TraitMakie's and TraitDifferentialEquations' rows were rerun after two fixes (the round's TraitMakie rows failed on an implicit forward, since fixed; the stated parameter's check is compiled into TraitWorld's image), and this chapter uses the reruns: `experiments/factscompiler/round/logs/makie-rerun.log` and `experiments/factscompiler/round/logs/tde-rerun.log`. Numbers of earlier builds and prototypes: the session note `../../session-notes/2026-10-18-29-reviews-and-decisions.md`, [`../record/design-history.md`](../record/design-history.md), [`../design-findings.md`](../design-findings.md) and the demonstrators' READMEs. A number marked "previous prototype" was measured on the package prototype, before the facts mode moved into Julia's compiler, and has no current counterpart yet.

**How to read the numbers.**
- One machine, mostly quiet during the round: one Julia process at a time.
- The forks' session (D0, E-212) ran with a load average of 1.5–2.7, the machine otherwise idle; E-233 with 0.1–0.6.
- Fresh processes, unless a row says "at the REPL".
- Runs per cell: 2 per load order for the demonstrators' rows, 3 for TraitReport, 2 after a warm-up for the forks. Ranges are over the runs. Treat differences under 10% as noise.
- "Plain" is the same code without traits, on the patched build in plain mode. The two inliner changes apply to all code, so patched-plain is not stock: stock numbers use the stock 1.13.2 binary and say so.

- **Again on the run of 2026-10-27** (E-163, `control.log`): the same. Plain: 14 of 212 and 562 of 4,694 lost; `all`: 0 of 200 and 2 of 3,337; upstream's work under `all` 502 ms first, 431 ms after the loads.
- **Before** (the build of 2026-10-19), upstream's work under `all` took 722 ms first and 992 ms after the loads. The compiler's own code compiled plainly in every compile queue (julia-1.13 f13117cd74) is the main change in between ([state](../state.md) §4).
- **Diagnosed on the build of 2026-10-19,** when it was ~990 ms: what upstream pays after the loads under `all` (now 435 ms, against 0.9 ms repeated; plain: 4.0 s) is the plain inference behind run-time `return_type`. Its cached answers rest on plain edges at abstract signatures (an `isapprox(::Integer, ::Integer)`, a `quantile!(::AbstractVector, …)`); the loads invalidate them (Unitful's `Colon(::Any, ::Any, ::Quantity)` alone 733 entries); `CSV.read` and `describe` ask again, and plain inference, optimizer included, runs again (70% of the profile then). This is by design: the answers are plain Julia's, so a load that changes plain inference changes them. The optimizer cannot be skipped: without it the answers get wider (CairoMakie's workload then fails) ([`performance.md`](performance.md)). The 435 ms has not been profiled again.
- **A second residue is diagnosed** (§3, TraitReport): StatsBase loads SparseArrays, a standard library, whose `vcat` for Base's `Number` and `Vector` wins at a fact signature inside `CSV._parse`. The design counts the standard libraries as Julia's own code ([glossary](../glossary.md) §1), so this is a stakeholder's change: not a pirate, not refused by strict mode (`TraitWorld/src/strict.jl:125`). Whether standard libraries should be separate owners is open ([`../open-issues.md`](../open-issues.md) §1.19).

E-281's session had no such caller. A flagged tension ([open issues](../open-issues.md) §1, GT-11).
- **The code slot as built** (E-283, `experiments/unification/stack/slot_cascade.jl`, `slot_cost.jl`, `slot_session.sh`, `slot_reload.jl`; `unified` 7500630036, product setting, strict mode off; 2026-11-07, load 2.5–4.5). Measures plain code and facts code calling plain code.
  - **Kept:** in the gate, a plain and a facts caller chain over a plain callee are kept through its recompilation to an equal result, and compiled again when the result changes; a caller from a package image is kept. The old world sees the old code.
  - **The cost:** a call through a slot takes 0.08 ns more where calls are independent of each other (1.418 against 1.336 ns, 10^8 calls, best of three, three runs per setting); nothing measurable where each waits for the last (1.588 ns both).
  - **The session:** W-106's workloads are no slower with the slot (`columns` 4.4 against 6.0 s, `ode` 4.6 against 6.3 s; TraitWorld's tests 25.3 against 27.1 s; one run per setting): a callee behind a slot is compiled at its first call, not with its callers; no code is kept there. With the slot off, the system image still calls through its own slots, so "off" covers the session's code only. They keep nothing: loading TraitWorld marks 208 of the 1,586 MethodInstances in its invalidation log, and the 142 left marked are the compiler's own code, which runs in its own world. The share in sessions that load packages after work: W-119.
  - **Image builds:** Base's `precompile` test, which builds package images, takes 251.6 s with the slot against 231.8 s without (+8.5 %, one run each); `core` 69.1 against 74.6 s. TraitWorld's image holds 15 % more machine code with the slot (13.7 against 11.9 MB) and builds in 25.9 against 24.2 s.
  - **Load:** `using TraitWorld` takes 2.11 s with the slot against 3.52 s without (one run each): a callee behind a slot is compiled at its first call, while a bound call has the JIT compile its callees with the caller. This is most of the workloads' difference above.
- **`Callable` by a memoized method-table query inside subtyping:** 1.4 µs for the first query per closure type, 75 ns repeated, 18 ns for a memo hit, against an entry's 80–96 ns (E-256). In an emulation, its rule for a question that reaches itself gave answers that depended on the order of questions (E-267, `experiments/unification/x6/`).

Where plain Julia reports at a call, the error is raised in the library or in Base under it, and names the function that failed there (`uppercasefirst`, `round`), not the operation the user got wrong.
- **The same, with a hint:** a value that is no member, and a type that never joined.
- **Worse in the trait form:** an operation called outside its declared signature. The hint gives the declared signature, but Julia's sentence for a thrown `MethodError` stands before it, and the user's own method is the second candidate ([open issue 177](../open-issues.md#2-design)).
- **Only in the trait form:** a member by its definition used before its `@implement`, whose message names the line to write; and a membership too new for running code, whose message is Julia's for a method too new (GT-14).
- **Refused, where plain Julia runs correctly:** the `Int` for a declared `Float64`.

## The earlier build's rounds: what they showed

Measured on julia-1.13, the build before the unified one, on one machine, in the measurement round of 2026-10-20 (julia-1.13 3b8085c222, TraitWorld bed3782) unless a row names another build or run. None of it is measured again on the unified build but where §1 to §4c say so. The rows are grouped by the step of [the rationale's argument](../design.md#2-the-argument-in-four-steps) they support.

**The four steps:**

- *Step 1, verified* in small cases (S4–S7), with the in-tree facts mode; proved in `../explorations/wrapping-by-facts.md`.
- *Step 2, verified* as a prototype: strict mode refuses winning pirates and nothing else in a real stack (837 pirates by the letter among 65,318 methods, none winning; measured on the previous prototype). Its intended design (pieces 1′, 14, 15, the extension rule, bindings) is not built.
- *Step 3, verified:*
  - the cases that are not fully typed (S1–S3, S8) invalidate on 1.13.2 and not in facts mode; acceptance 35 of 35 in both settings (2026-10-29);
  - G2 across package loads, product setting: 0 of 15,030 CodeInstances of the facts owner lost after each of ten loads, in either load order (E-29, 2026-10-28);
  - **the control:** under `all`, nine unrelated loads cost PlainTables 0 of 244 CodeInstances (plain mode: 14 of 256) and upstream CSV + DataFrames 2 of 3,337 (plain: 561 of 4,684). Load protection is the facts rule's property, for any code.
- *Step 3's cost:* the full BaseBenchmarks under `all`: geometric mean 1.037 against plain (1.030 on the run of 2026-10-27); tails up to 27.8×, on containers of `Any`. Before (an earlier build, before parts B–D): 1.016, tails up to about 80×.
- *Step 4:* traits recover the tail tried: the raytrace through `Dynamic` (below; the build of 2026-10-19). `parse_json`'s tail is recovered by typed captures, 1.17× the fixed plain code (an earlier build), a fix plain Julia makes too (`local pos::Int`), so it is no evidence for traits. The fully-typed certificate is built (`fully_typed`, fully typed mode).

**Shown on the earlier build:**
- **The facts mode by itself, on the packages people use.** Upstream CSV.jl and DataFrames compiled in the facts mode (`all`) lose 2 of 3,337 CodeInstances to nine unrelated loads, against 561 of 4,684 in plain mode. Their first work takes 516 ms instead of 3,308 ms, and 435 ms after the loads instead of 4,021 ms. No trait is involved: the guarantee of step 3, and a first-call gain, for code as it is written today.
- **Traits on top, against upstream and pandas:** the trait-based ports of CSV.jl and DataFrames run a scripted session in 4.71–4.83 s wall against upstream's 12.55–12.79 s and pandas' 0.54 s (E-233); in D0 (E-212), 4.4–4.5 s against upstream's 11.9–12.5 s plain, 9.6–10.5 s wrapped as trait modules and 7.5–7.6 s under `all`; without start and imports, 1.82–1.87 s against 10.5–10.7, 7.9–8.7 and 6.5 s (D0, E-212). The facts mode alone takes upstream from 10.6 to 6.5 s; the traits take it to 1.8 s. The forks' imports are 1.7 s slower than upstream's under `all`.
- **Calls cost what plain calls cost, where types are known.** A typed trait call: 0.8 ns, as plain Julia, in both settings. A `Callable` held `Dynamic`: 3.95 ns, against 0.87 ns for a direct call and 20.3 ns for a dynamic call at `Any`.
- **Untyped trait calls cost 3.4–5.4× a plain untyped call on the erased worker's path:** 59.9 ns against 17.6 ns (product setting), 106.2 against 19.6 ns (`all`), 80 bytes per call (the run of 2026-10-27; W-17). Before, through the table of declared implementations (the round): 28.8 and 30.8 ns, 16 bytes.
- **`Dynamic` values at near plain speed** (the build of 2026-10-19). A sum over `Dynamic{Shape}`: 0.92–1.40 ns per element against plain's 0.87–0.91 with two types and 29.5–33 with four. The raytrace over an open set of primitives: 300–336 ms against plain's 246–259 with two types and 827–882 with four (a `max_methods` effect at four).
- **Traits bring load stability where the facts rule cannot: a package's own extension.** CSV.jl's extension for InlineStrings adds methods to CSV's internal functions. Loaded with DataFrames, it discarded the reader's code: the first read took 2.5 s against 0.19 s. That is a stakeholder's change ([the rationale §2.2](../design.md#22-step-2-refuse-the-pirates-that-would-win-and-fully-typed-code-is-never-invalidated)), which the facts rule follows. TraitCSV declares an implementation for `String15` in its extension instead, and loading InlineStrings discards none of the reader's code. Measured on the package prototype; not rerun on the compiler. The coding pattern traits bring (extension by implementations, never by methods on a library's internals) is what protects even well-trodden parts of the ecosystem.
- **New trait code costs about the same in every load order.** A new problem type in TraitDifferentialEquations: `@implement` 123–165 ms, its first solve 324–336 ms, most of it the solver compiled for the new key, with CSV, DataFrames and CairoMakie loaded before, after or not at all (the run of 2026-10-27; three rows differ by load order, §3). A new data type in TraitMakie: `@implement` 47–67 ms, first PNG 76–110 ms (timed inside `@elapsed`, without the call's own compilation). Slower than on the round's builds (`@implement` 66–74 and 22–47 ms; W-7).
- **Compiling per key, not per closure.** A new callback closure 24–25 ms, a second 30–32 ms; a second loss closure 49–50 ms; ForwardDiff's own tag 773–810 ms; in every load order (the run of 2026-10-27).
- **Sessions.** TraitReport in a fresh process: 0.834–0.861 s; without traits 0.740–0.757 s (the run of 2026-10-27); Python (pandas 3.0.6, matplotlib 3.11.2) 0.578–0.589 s (the round). Under nine loads, the trait module's work over upstream CSV.jl takes 333–344 ms against its plain twin's 2,991–3,106 ms.
- **The solver's run time** (the run of 2026-10-27). 169 ns per step for Lorenz against OrdinaryDiffEq's 336 ns; 7.8 µs against 6.15 µs at n = 1,000.
- **AOT:** a trimmed TraitMakie binary of 4.07 MB (built under the previous prototype's policy; not rebuilt on the compiler).
