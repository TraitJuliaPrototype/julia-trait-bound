# The state of the prototype (2026-10-29)

The prototype works end to end. Traits run at plain Julia's speed for typed calls, and the facts compiler stops invalidation. On the compiler side, the work reduces to four mechanisms, plus hooks for the library and fixes.

For core developers. The design itself is the four [references](reference/README.md), each with a Deviations table; this page summarizes them. The changes to Julia by principle are the [compiler reference](reference/compiler.md), with the inventory in [`design/julia-changes.md`](design/julia-changes.md); the measurements are in [`design/evidence.md`](design/evidence.md).

## 1. Where the project stands

### Traits

The library, TraitWorld, works end to end:
- **The design:** three rules, keys instead of representations, and every value in trait code `Compiled` or `Dynamic` ([traits §6](../attic/writeup/reference/traits.md#6-values-in-trait-code-compiled-and-dynamic)).
- **`Compiled` and `Dynamic`** (TraitWorld 7fc229c, 2026-10-20; W-4): a value is `Compiled` where the code that passes it knows its type, `Dynamic` where it does not, overridden by attributes on bounds and item parameters and by the casts `compiled_for`, `with_dynamic`, the later cast winning; `Dynamic` is a trait object at an erased key, one worker per key; values carry their attribute through storage (TraitWorld 1d09112, 2026-10-21; W-18): a trait's name in a field or container means `Kept{X}`, one concrete type holding the user's object and its attribute, `Compiled{X}` is a value beside `Dynamic{X}`, constructors never cast, and a struct parameter bounded by a trait keeps the value itself or a `Dynamic{X}` ([traits §7](../attic/writeup/reference/traits.md#7-kept-values-dynamicx-compiledx-keptx), [§7.4](../attic/writeup/reference/traits.md#74-a-struct-parameter-bounded-by-a-trait)); `Callable{A, S}` defaults to `Dynamic`; items of collections cross as `CompiledItems` or `DynamicItems`. The demonstrators run on it; a loop over a value compiled for its type opens it by an `Opened{X}` bound (TraitWorld e99851b), or its caller casts it with `compiled_for`; a library that changes a user's function keeps its attribute with `rewrap(g, f)` (TraitWorld a8c9c26); a function kept at a struct parameter reads back with its attribute (TraitWorld 29b6df4); a function can be kept before its signature is known, `Kept{Callable}` (TraitWorld c39fedc). Deviations: [traits T-47 to T-50](../attic/writeup/reference/traits.md#17-deviations), [lowering L-31, L-35](../attic/writeup/reference/lowering.md#18-deviations); performance gaps where trait code should be as fast as plain code: [W-17](record/todo.md).
- **Beyond the `Dynamic` split, a table** (julia-1.13 711484a23e, the C ABI rule 6d480d0753, 2026-10-21; E-145): a value of a type outside the split's four is called through a table of the call's targets keyed by its type, one probe and an indirect call, no allocation (18 ns per element at 64 implementations, 77 before) ([compiler §4.3](../attic/writeup/reference/compiler.md#43-what-follows-the-split-the-table-of-a-calls-targets)); `compiled_for` from an untyped caller goes through the table of declared implementations (TraitWorld a747d4a).
- **TraitDifferentialEquations around `ODEProblemTrait`** (e37829f, 2026-10-21; W-2): a problem is any type that implements the trait, TDE's `ODEProblem` the canonical one, its function kept at two struct parameters bounded by `Callable` (W-18); `solve(prob, alg)` the one entry point.
- **BaseTraits** (TraitWorld 9fd18db, 2026-10-20): collection traits for Base's concepts, Base's containers conforming; `Dynamic` holds the user's object (5 ns to make one), the split's candidates in declaration order; a container with untyped items crosses implicitly, by the bound ([traits §7](../attic/writeup/reference/traits.md#7-kept-values-dynamicx-compiledx-keptx)).
- **Load and first use** (W-58, 2026-10-27; [the plan](plans/2026-10-27-ttfx-sciml-makie.md), [evidence §3](design/evidence.md#3-first-calls-and-sessions)): the trait demonstrators' whole session (load, a non-stiff and a stiff solve, a plot, a second model) takes 0.96 s against Python's 1.45 s; a generated trait world of 4,000 workers loads in 0.30 s and takes a new type in 0.08 s (E-171); compiled by facts, Makie's code survives a later `using DataFrames` (0.02 s recompiled against 6.1 s plain, E-177). Fixed on the way: TraitWorld's hooks compiled at every session's first load (04095fe), `@implement` growing with the library (003ce8f), the facts images' load (julia-1.13 6800be7839, W-59).
- **The demonstrators** pass their suites: TraitDifferentialEquations, TraitMakie, and TraitReport with its packages TraitTables and TraitCSV. The forks of Tables.jl, CSV.jl and DataFrames.jl pass their upstream suites (E-211, W-14).

### Facts

The facts compiler is built, with two settings:
- **The product setting:** only trait modules are compiled by facts.
- **`all`:** everything is compiled by facts. It is the test bed.

- **Correctness:** the acceptance checks pass, 35 of 35, in both settings (2026-10-29, the builds of §6.1).
- **G2 across package loads** (E-29, 2026-10-28): in the product setting no CodeInstance of the facts owner is lost after any of ten loads, in either load order; under `all` the only losses come from a standard library's method, which is Julia's own owner ([evidence §1](design/evidence.md#1-the-guarantee)).

Measured in the round of 2026-10-20:
- **The payoff under `all`:** upstream CSV+DataFrames lose 2 of 3,337 CodeInstances to nine unrelated loads (plain: 561 of 4,684). Their first work takes 516 ms (plain 3,308 ms), and 435 ms after the loads (plain 4,021 ms).
- **The cost under `all`:** the full BaseBenchmarks (4,342) run at a geometric mean of 1.037 against plain, with tails up to 27.8× on containers of `Any`. The quick subset (148, chosen to include the tails) gives 1.710; it is not the average cost.

The details, with every row: [`design/evidence.md`](design/evidence.md).

## 2. The compiler changes as four mechanisms

The patched Julia's size is in [`design/julia-changes.md`](design/julia-changes.md). Underneath its changes are four mechanisms.

| # | Mechanism | What it does | What it covers | General for Julia? |
|---|---|---|---|---|
| 1 | **Infer across a call only where a fact holds** | A call is inferred, with an edge, only at a signature that only its stakeholders or a pirate can change. Every other call is a run-time site. | Part (A), `is_fact_sig` | As "a facts mode for the native compiler" |
| 2 | **Each method's code is compiled in a mode decided by the method and the mode that reaches it** | Code compiled by facts and plain code live side by side, with separate caches, edges and images. A trait module's methods are compiled by facts and the compiler's own code plainly, whoever calls them; other methods get one copy per mode that reaches them. | Parts (B) and (C); one function for the mode and owner, `jl_code_owner` (§4); the compiler's never-by-facts flag; inlining from the other owner's cache (piece 10, c7f1eae); edges and image copies for the second owner (pieces 9 and 5, 9892bfc) | As per-method inference modes |
| 3 | **Caches at dynamic boundaries are checked against the caller's world** | A cached dynamic call or `cfunction` pointer runs in the caller's world, as Julia's own caches already do. | The `:caller_world` cfunction convention (piece 18); exact-type and wildcard entries in the per-call-site dispatch cache | Yes |
| 4 | **Two primitives for a specialized path beside a general one** | `known_type` folds to whether inference knows a value's concrete type (GCC's `__builtin_constant_p`, for types). `split_call` splits a call site over registered candidates. | `known_type` (b5bb9ab); part (D) | `known_type`: yes |

Mechanisms 1 and 2 are the facts compiler. Mechanisms 3 and 4 are general improvements that the facts mode made necessary.

## 3. Besides the four mechanisms

- **Hooks for the library:**
  - method-definition hooks (piece 1), for strict mode;
  - field-offset intrinsics (piece 3), for trait objects;
  - a registry of type printers (piece 17).
- **General fixes, useful without traits:**
  - two inliner changes: exact specializations over a widened varargs tail, and cycle members inlining each other;
  - the run-time `return_type` entry compiled into the system image;
  - reflection running in the compiler's world for an explicit `NativeInterpreter`.
- **Bug fixes of our own:**
  - `return_type_tfunc` captured type values in a closure;
  - the compile queue that builds images compiled the compiler's own code by facts (§4).
- **A tool:** the dispatch profiler (`JULIA_FACTS_DISPATCH_PROFILE=1`): dynamic calls per callee and per call site, with a reset to profile one region.
- **On branch `unified`** the general fixes, the per-call-site cache's wildcard entries, `:caller_world` and the profiler (named `JULIA_DISPATCH_PROFILE=1` there) are the stack's first eleven commits, without their facts halves ([julia-changes §7.1](design/julia-changes.md#71-the-stack)).

## 4. Mechanism 2 is one rule in the code

Which mode and owner a method's code gets is decided by one function, `jl_code_owner` ([compiler §2.3](../attic/writeup/reference/compiler.md#23-the-owners-and-the-mode-and-owner-of-a-methodinstances-code)), given what reaches the code: the runtime or the top level, plain code, or code of the facts owner. The runtime's default owner, its dispatch from facts code, the calls between the modes in inference and the compile queues all ask it. It has one predicate for "compiler code", the module flag. The setting decides only what code reached from the runtime gets, and the mode is the owner.
